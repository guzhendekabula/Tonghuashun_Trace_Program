# 股价异动解释时间线 · 需求文档

版本：v1.0  
日期：2026-10-24  
用途：24 小时笔试项目的开发与验收依据

## 1. 项目目标

使用 React + TypeScript 构建可在浏览器运行的交互网页。用户选择虚构股票及异动日期，通过 K 线、事件时间线、事件详情与浮动聊天助手，了解可能影响股价的事件及证据，并清楚区分事实、观点、时间相关性和未证实的因果假设。

项目全部业务数据内置，不使用真实行情、联网采集或真实大模型。Agent 使用结构化预设内容、规则匹配和模拟流式输出，不需要 API Key 或模型调用费用。界面明确标注“模拟数据”和“模拟 Agent”。

## 2. 已确认范围

| 项目 | 要求 |
| --- | --- |
| 技术 | React + TypeScript，纯前端；使用当前 Vite 项目作为基础 |
| 股票 | 三支虚构股票 |
| 行情范围 | 连续三个完整自然月，以内置交易日历为准，约 60 个交易日 |
| 月 K | 三根，由对应日 K 聚合 |
| 日 K | 每个交易日一根，约 60 根；默认图表周期 |
| 时 K | 选中交易日的四个一小时交易区间，跳过午休，支持前后交易日切换 |
| Agent | 浮动入口、聊天窗口、自动发起查询、快捷提问、可编辑输入框、模拟流式回答 |
| 风格 | 清新、大气、专业；除行情涨跌外保持统一主色调 |
| 数据与运行 | 内置固定模拟数据；启动后不依赖外部数据服务、字体 CDN 或模型服务 |

不纳入首版：真实证券查询、登录、交易操作、真实模型、多轮语义推理、自动采集、复杂指标、服务端持久化。聊天记录仅在当前页面会话内保留，刷新可重置。

以下细则为基于已确认范围制定的首版默认实现规则，可在开发过程中调整，但不得削弱题目验收要求。

## 3. 模拟场景与数据

### 3.1 股票

| 虚构股票 | 主要演示场景 |
| --- | --- |
| 澄芯科技 | 业绩公告及财务改善与上涨日存在时间关联 |
| 沐光能源 | 行业负面事件与下跌日存在时间关联 |
| 云禾消费 | 明显波动但证据较弱，助手明确说明解释不足 |

使用内部模拟代码，不冒用真实证券代码。每支股票均提供完整三个月行情、至少一个异动日、关联事件及财务记录；整体覆盖明显上涨和明显下跌。三支股票均应能演示完整交互，不能只有第一支可用。

事件类型覆盖公告、新闻、行业事件和财务披露。数据中包含盘前、盘中、盘后、周末或模拟休市日、不同原始时区、无关联事件、证据不足等场景。所有来源均明确标注模拟来源，证据正文保存在本地，不伪造可访问的真实新闻链接。

### 3.2 行情一致性

以固定时 K 数据为基础聚合日 K，再聚合月 K；也可在开发阶段生成后保存为固定文件。禁止运行时无种子随机生成。

- 开盘价取区间内第一根的开盘价，收盘价取最后一根的收盘价。
- 最高价取最大值，最低价取最小值，成交量求和。
- 价格为正，成交量非负；最高价不低于开盘价和收盘价，最低价不高于两者。
- 模拟时 K 区间为 09:30–10:30、10:30–11:30、13:00–14:00、14:00–15:00，显示区间而非含糊的整点标签。
- 数据日期和价格在实现阶段固定，README 记录数据范围和生成方式。
- 可额外提供首个显示交易日前的参考收盘价；若没有，则首日涨跌幅显示“—”，不判定异动。

交易日历除行情覆盖范围外，须包含尾部必要的下一交易日，以便映射最后一个交易日盘后的事件。模拟休市安排属于本项目日历，不宣称完整复刻真实交易所节假日。

## 4. 页面布局与视觉

桌面浏览器优先，建议重点适配 1280px 及以上宽度；窄屏允许区域上下排列，关键内容和按钮不被遮挡。

1. 顶部：项目名称、模拟数据标识、三支股票选择、当前股票摘要。
2. 主图区域：月／日／时周期切换、K 线、日期范围、选中状态、异动标记。
3. 事件时间线：当前日期、关联事件列表、事件类型及语义标签。
4. 事件详情：标题、发布时间、映射交易日、类型、来源、摘要、证据。
5. 右下角：浮动 Agent 入口与可收起的聊天窗口。

浅灰白背景、白色卡片、深灰文字，以低饱和蓝色统一按钮、选中状态、时间线和助手。上涨使用红色，下跌使用绿色，并配合正负号和文字，避免仅依赖颜色。语义标签用文字、轻量底色或边框区分，不使用大面积多彩装饰。

按钮具有可理解的文本或可访问名称；键盘可操作主要控件；模拟流式输出不应持续强制抢夺焦点。浮动窗口不得遮住自身关闭按钮或使关键页面操作无法访问。

## 5. 图表与联动

### 5.1 默认行为

- 首次进入选择第一支股票，使用日 K，并选中该股票最近一个异动日。
- 所选日期同步驱动图表高亮、事件列表和 Agent 当前分析对象。
- 切换股票后选择该股票最近一个异动日；若无异动则选择最近有效交易日并说明无异动。
- 普通交易日也可以选择；没有达到阈值时不得称其为明显异动。

### 5.2 周期交互

| 周期 | 行为 |
| --- | --- |
| 日 K | 显示约 60 根，突出异动日；点击任一交易日更新当前日期 |
| 月 K | 显示三根；标明当月是否含日级异动；点击月份切回该月日 K，并选择该月最近异动日，无异动则选择该月最后交易日 |
| 时 K | 展示当前日期四根时 K；前后切换按交易日历跳过休市日，并更新当前日期 |

月 K 的异动标识表示“月内存在日级异动”，不能冒充月级异动判断。点击小时柱只更新小时高亮，事件和助手仍以该交易日为分析单位。

### 5.3 事件联动

- 选择日期后，以映射交易日等于所选日期的事件作为当日关联事件，自动定位并高亮。
- 事件按实际发布时间升序排列；详情同时保留原始时间和交易所时间。
- 点击事件打开详情并同步选中状态。
- 点击 Agent 证据引用，定位并高亮时间线事件，同时打开详情；必要时切换至该引用所属股票和分析日期。
- 首版不提供任意背景事件窗口；解释引用的财务记录和历史材料必须在事件证据中明确列出，不能把历史材料伪装成当日发布事件。

## 6. 异动与时间映射规则

### 6.1 日级异动

当日涨跌幅 =（当日收盘价 − 前一交易日收盘价）÷ 前一交易日收盘价。

绝对涨跌幅 ≥ 5% 标记为异动。阈值是本项目演示规则，不代表交易所官方标准。使用原始数值判断，显示时再四舍五入。缺少有效前收盘价或行情异常时不计算，不默认填零。

### 6.2 时间映射

统一交易所时区为 `Asia/Shanghai`。原始事件时间须为携带 UTC 偏移或 Z 的 ISO 8601 时间；无时区或无法解析的时间视为异常，不猜测。

1. 先转换到交易所时区，再取当地日期和时间。
2. 当地日期为交易日且发布时间早于 15:00:00：映射至当日，包含盘前、交易中与午休。
3. 交易日 15:00:00 及以后：映射至下一交易日。
4. 非交易日：映射至下一交易日。
5. 下一交易日只从内置日历查找，不仅依据周末推断。
6. 有映射交易日但超出行情显示范围：标记“超出行情范围”，允许查看详情，不错误高亮边界日期。
7. 日历中不存在可用的下一交易日：标记“交易日历不足，无法映射”，不凭空生成日期。

15:00:00 归下一交易日是本项目边界约定。事件属于哪一财务报告期，不决定其映射日期；以披露时间为准。盘后事件不能作为当天已发生行情的解释；盘中事件也不能声称解释其发布之前的小时波动。

## 7. 证据与解释语义

| 标签 | 含义 |
| --- | --- |
| 事实 | 模拟资料明确记载、可在本地证据中核对的陈述 |
| 观点 | 来源或评论者的判断，不当作客观事实 |
| 时间相关性 | 事件与波动在时间上接近，不构成因果证明 |
| 因果假设 | 对影响机制的可能解释，尚未证实 |

标签附着在具体陈述上。事件类型与语义类型是两个字段；同一事件可包含事实和观点，事实证据支持的影响解释仍可能只是因果假设。

每个因果假设必须包含依据、证据引用、置信度及理由、不确定性提示。置信度使用低／中／高，表示预设规则的支持程度，不是统计概率；高置信度也不得称为已证实因果。

缺少有效证据时，不生成肯定式因果陈述；显示“证据不足”，置信度为低并解释缺失内容。通常输出 1～3 个因素；无可支持因素时允许零个，并明确解释不足，不能为凑数量虚构证据。

## 8. 浮动聊天 Agent

### 8.1 入口和自动查询

- 点击浮动入口打开聊天窗口，包含标题栏、当前股票与日期、消息列表、快捷问题、输入框、发送和停止按钮。
- 首次打开时自动插入用户消息：“请分析【股票】在【日期】的股价异动，并提供相关事件和证据。”随后开始模拟回答。
- 同一分析上下文收起再打开不重复发送；若当前上下文尚未查询，则打开时自动查询。
- 收起窗口不清空记录；已开始输出可以继续。

### 8.2 回答内容与流式效果

基于股票、日期和问题意图查找结构化预设回答，并校验事件及证据引用。回答按小段逐步出现，不能一次展示全文后伪装流式。先显示整理中状态，再输出行情概述和最多三个因素；因素完成后展示对应证据按钮。

支持停止输出；停止后保留已有内容并标记“已停止”，可重新生成。输出期间禁止重复提交，防止并发消息交错；完成或停止后恢复输入发送。

### 8.3 快捷提问与自由输入

快捷问题至少包含“分析当前日期”“查看主要证据”“为什么不能确定因果”。点击后插入可见用户消息，并调用对应预设响应。

输入框可编辑、发送、清空；Enter 发送，Shift+Enter 换行，中文输入法组合输入期间不误触发送；空白消息不发送。自由输入使用有限关键词匹配上述意图，始终围绕窗口标示的当前股票和日期，不承诺任意问题理解或多轮记忆。

无法识别的问题也必须得到明确响应，例如：“当前为模拟演示，支持分析当前日期、查看主要证据和解释因果不确定性。请选择下方快捷问题。”同时展示可操作快捷入口。不得无视用户问题，直接返回不相干分析。用户若要求查询其他股票或日期而系统不能识别，应提示通过页面选择器切换。

### 8.4 上下文切换与历史消息

- 切换股票或日期时停止未完成回答，标记其已中断，更新窗口当前分析对象。
- 窗口已展开时提示“分析对象已切换”，提供“分析当前日期”按钮，不自动连续发问。
- 每轮消息保存自身股票与日期，旧内容不改写成新日期。
- 旧回答的证据按钮使用该轮保存的上下文定位，不能错误引用当前日期的事件。
- 窗口内持续可见“模拟 Agent · 基于内置数据与预设规则”。

## 9. 核心数据结构

以下为逻辑字段约束，具体 TypeScript 类型在实现时细化。

| 实体 | 必备字段 |
| --- | --- |
| Stock | id、虚构代码、名称、行业、exchangeTimezone |
| TradingDay | date、isTradingDay、交易区间；可选休市说明 |
| Candle | stockId、周期、开始／结束时间、交易日期、open、high、low、close、volume |
| Event | id、stockIds、title、publishedAt、type、sourceId、summary、statements、evidenceIds |
| EventMapping | eventId、exchangePublishedAt、mappedTradingDate、status、reason |
| Source | id、名称、模拟来源标识；可选本地文档标识 |
| Evidence | id、sourceId、原文摘录或结构化数值、定位说明；可选 financialRecordId |
| FinancialRecord | id、stockId、报告期、披露时间、指标名称、数值、单位、同比值、sourceId |
| Statement | 文本、事实／观点／时间相关性／因果假设标签 |
| ExplanationFactor | id、stockId、analysisDate、陈述、语义标签、eventIds、evidenceIds、置信度及理由、不确定性、证据状态 |
| ChatMessage | id、角色、股票与日期上下文、问题意图、内容、生成状态、引用 |

映射结果和异动结果由统一规则计算，避免图表、时间线和助手各写一套。引用必须指向存在的记录；无效引用触发证据不足状态，不渲染无效跳转。财务数据必须参与至少一个可见解释场景。

## 10. 状态与异常

提供可重复触发的“演示场景”切换入口，正常场景为默认。异常场景使用独立固定数据，避免污染正常数据。

| 状态 | 展示与行为 |
| --- | --- |
| 加载中 | 行情／事件显示占位；Agent 显示整理或输出状态 |
| 无行情 | 明确空状态，提供恢复正常场景入口 |
| 日期无事件 | 保留有效行情，时间线说明没有相关事件，助手不编造因素 |
| 范围外事件 | 单独标注并可查看详情，不映射到错误的可见 K 线 |
| 时间异常 | 说明时间不可解析或缺少时区，排除关联计算 |
| 行情异常 | 标记无效记录，禁止用于异动计算；不得连接或补造不存在的 K 线 |
| 日历不足 | 提示无法确定下一交易日 |
| 证据不足 | 展示低置信度及不确定性说明，禁用无效证据链接 |
| 输出中断 | 保留已输出内容，支持再次查询 |

局部异常不导致整页崩溃，且错误提示能指出受影响的数据或操作。

## 11. 测试与验收

### 11.1 自动化测试

至少完成题目要求的前三项，建议将以下规则测试一并覆盖：

1. 盘后事件：交易日 15:00 之后映射到下一交易日。
2. 非交易日事件：跳过周末及日历明确标记的休市日。
3. 证据不足的因果假设：返回证据不足、低置信度及不确定性，不返回已证实因果表达。
4. 时间边界：14:59:59 当日，15:00:00 下一交易日；跨时区输入按转换后的当地时间判断。
5. 聚合一致性：时 K 到日 K、日 K 到月 K 的 OHLC 和成交量正确。
6. 上下文切换：停止旧输出，旧回答引用仍指向原始上下文。

### 11.2 人工验收清单

- [ ] 三支股票都可切换，模拟标识清晰。
- [ ] 月 K 三根、日 K 约 60 根、选中日时 K 四根，聚合一致。
- [ ] 默认日 K，至少展示一个上涨和一个下跌异动场景。
- [ ] 选择异动日自动定位并高亮事件；详情字段完整。
- [ ] 不同原始时区统一显示，盘后和非交易日映射正确。
- [ ] 因果假设展示依据、置信度和不确定性。
- [ ] 点击 Agent 自动提问，回答具有可见流式过程。
- [ ] 快捷提问及手动发送可用，未知问题有合理兜底。
- [ ] 回答中的证据能跳转到事件，旧消息不会串用新上下文。
- [ ] 加载、空数据、范围外事件和异常数据均可主动演示。
- [ ] 三个必需测试通过；生产构建成功。
- [ ] 运行时无需外部行情或模型服务。

## 13. 24 小时实施顺序

优先完成数据和纯函数规则、日 K 与时间线联动、证据详情、聊天流式闭环及三项必需测试；随后完善月／时 K、异常演示、视觉与交付文档。三个周期均属于已确认交付范围，顺序只用于降低开发风险。

建议时间分配：需求与数据 3 小时，图表与联动 6 小时，Agent 4 小时，异常状态及测试 4 小时，视觉检查与 README／对话记录整理 3 小时，预留 4 小时修复问题。不增加与题目无关的功能。
